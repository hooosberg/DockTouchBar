### ⚡ 에너지 및 기본 성능(이전 릴리스 측정값)

이벤트 기반 앱 및 윈도우 업데이트를 사용하여 24/7 백그라운드 상주용으로 엔지니어링되었습니다. 아래의 측정값은 이전 릴리스에서 나온 것이며, 스크린샷 활동은 일시적으로 짧은 프로세스 확인을 사용합니다:

| 지표 | 측정값 | 참고사항 |
|---|---|---|
| **CPU 사용률** | **0.0% ~ 0.8%** | 유휴 0.0%; 앱/윈도우 전환 이벤트에서만 무시할 수 있는 짧은 급증 |
| **물리적 메모리 사용량** | **29 MB** | macOS `footprint` 도구로 측정, 전자 대안의 일부 |
| **에너지 영향** | **0.0** | macOS Activity Monitor의 최하 에너지 등급, 배터리에 미치는 영향 없음 |
| **상주 스레드** | **4 스레드(모두 이벤트 대기 중)** | 바쁜 대기 없음, 고주파 타이머 폴링 없음 |
| **네트워크 접근** | **GitHub 업데이트 확인 및 다운로드** | 독 상호작용은 로컬에서 실행; 분석 또는 계정 없음 |
| **렌더링 레이턴시** | **~2.3 ms / 프레임** | 즉각적인 터치 응답성을 위한 기본 CoreAnimation / AppKit 렌더링 파이프라인 |

**DockTouchBar가 도움이 되었다면, GitHub의 ⭐ 스타는 감사의 최고의 표현입니다.**

## 왜?

Pock, PockV2 및 유사한 앱들은 독을 터치 바에 올려놓을 수 있지만, 많은 일을 하기 때문에 일상 사용에서는 바가 사라지거나 응답하지 않는 경향이 있습니다. DockTouchBar는 한 가지 작업을 수행하고 그것을 잘 합니다.

**간단함**

- 한 가지 작업: 터치 바에 나타나는 독. 위젯, 플러그인 없음.
- 메뉴 바에 몇 개의 스위치만 있고, 설정할 것이 더 없음.
- 제3자 의존성 없는 기본 Swift 및 AppKit. 픽셀 아트 장면은 소스에 포함됨.

**우아함**

- macOS 아이콘과 시스템 터치 바 스크롤러를 사용합니다. 고정되지 않은 실행 중인 앱은 왼쪽에 표시되며 최신 앱이 먼저 나타나고, 고정된 앱은 독의 순서를 유지합니다. 앱을 닫으면 현재 보이는 영역이 유지됩니다.
- 방해하지 않는 제스처: 탭은 즉시 작동합니다(이중 탭 여부를 확인하기 위해 기다리지 않음). 길게 누르면 아이콘 아래에 진행 막대를 표시하고, 터치 바의 우측 끝에 "종료 중..." 카운트다운을 표시합니다. 손가락이 이를 가리지 않도록 픽셀 아트 장면으로 그려지며, 네 계절 중에서 전환할 수 있습니다. 조기 해제하여 취소 가능.
- 빠른 탭이 자연스럽게 느껴집니다: 마지막 탭이 항상 우선되며, 저항하지 않습니다. 시스템이 데스크톱 전환을 놓치거나 뭔가 포커스를 빼앗으면, 조용히 문제를 바로잡고, 키보드, 마우스 또는 트랙패드에 닿는 순간 멈춥니다.
- 당신의 언어로 말합니다(12개 언어, 영어에서 简体中文 및 日本語까지). 선택적 권한은 단 하나만 요청합니다.

**효율성**

- 이벤트 기반 앱 및 윈도우 업데이트. M1 MacBook Pro에서 이전 측정값, 독이 표시되고 유휴 상태일 때: **0.0% CPU**, **0 유휴 웨이크업**, 약 **32 MB** 메모리.\*
- 고정된 지연을 사용하는 대신 Mac에 맞춰 조정합니다: 데스크톱 전환은 시스템의 자체 "완료" 신호를 기다리고 결과를 확인하므로, 애니메이션이 느리거나, 꺼져 있거나, 컴퓨터가 바쁜 경우에도 올바르게 유지됩니다.
- 앱이 시작되거나 종료될 때, 변경된 부분만 업데이트되고 스크롤 위치가 유지됩니다. 아이콘은 한 번 래스터화되어 캐시됩니다.
- 자체 치유: 절전 모드, 화면 잠금 해제 및 제어 스트립 재시작 후 다시 연결되므로, 재시작할 필요가 없습니다.
- 안전하게 실패: 개인 API는 런타임에 확인됩니다. macOS가 하나를 제거하면, 충돌하는 대신 그 기능이 자동으로 꺼집니다.
- 개인 정보 보호: 분석 또는 계정 없음. 독 상호작용은 로컬에서 실행되고, 자동 업데이트 확인 및 요청된 다운로드는 GitHub에 연결됩니다. 기본 설정은 Mac에 남아 있습니다.

<sub>\* 릴리스 빌드. CPU는 2초 간격으로 5개의 `top` 샘플에서 나온 값(모두 0.0%); 웨이크업은 1.10에서 20초 간격으로 읽은 커널의 프로세스별 카운터에서 나온 값(3번 0 유휴 웨이크업 및 0 인터럽트 웨이크업; 1.8에서의 이전 실행은 시스템 이벤트로 인해 0~7 인터럽트 웨이크업을 보임); 메모리는 `footprint`에서 나온 물리적 메모리 사용량(32 MB). 커피 잔 위의 연기는 앱이 아닌 시스템의 렌더 프로세스로 그려집니다.</sub>

## 기능

| 제스처 | 수행되는 작업 |
|---|---|
| **탭** 아이콘 | 앱으로 전환하거나 실행합니다. 창이 다른 데스크톱(공간)에 있으면 해당 데스크톱으로 이동합니다 |
| **이중 탭** | 현재 윈도우를 최소화합니다(노란색 버튼처럼). 손쉬운 사용 권한이 필요합니다. 다시 탭하여 복원 |
| **길게 누르기** | 앱을 닫고 항상 발생한 상황을 알려줍니다. 누르는 동안 아이콘 아래에 진행 막대가 채워지고, 터치 바의 우측 끝에 "종료 중..." 카운트다운이 픽셀 아트 계절 위에 나타납니다(메뉴에서 선택 가능). 조기 해제하면 탭으로 계산됩니다. 앱은 항상 완전히 종료되며(⌘Q와 동일), 윈도우 개수나 최소화 또는 숨겨진 여부에 관계없이 작동합니다. Finder는 종료할 수 없으므로 모든 윈도우가 닫힙니다(최소화된 윈도우도; 다른 데스크톱에 있으면 먼저 이동). 앱이 대기(저장되지 않은 변경사항 시트) 또는 닫히지 않아 닫을 수 없으면, 터치 바가 데스크톱을 넘어 이로 전환하고 이를 알려줍니다 |
| **휴지통** | 탭하면 Finder에서 휴지통 윈도우를 엽니다; 이중 탭하면 최소화합니다; 길게 누르면 닫습니다. 윈도우가 닫혀 있을 때 어두워집니다("실행 중인 앱만 표시" 모드에서는 사라집니다) |
| **스와이프** | 아이콘이 모두 맞지 않을 때 스크롤합니다; 앱을 닫으면 현재 영역이 보기에 유지됩니다 |
| **커피 잔**(우측 끝, 애니메이션되는 연기 포함) | 휴식을 취하세요: 독을 잠시 숨기고 터치 바를 시스템(밝기, 볼륨)에 반환합니다. 10~60초 후 자동으로 반환됩니다 |
| **중앙 / 최대화 버튼**(우측 끝) | 최전면 앱의 윈도우를 중앙에 맞춥니다; 다시 탭하여 최대화합니다(사용 가능한 영역을 채우고, 기본 전체 화면 아님), 다시 탭하여 중앙에 맞춥니다. 윈도우를 직접 이동했거나 앱을 전환한 경우, 먼저 중앙에 맞추고 아이콘이 윈도우의 현재 상태를 따릅니다. 손쉬운 사용 권한이 필요합니다 |

메뉴 바 메뉴는 일일 스위치를 유지합니다: 터치 바에 독 표시, 실행 중인 앱만 표시(기본값은 해제: 고정된 앱도 표시됨; 어두워질 수 있는 앱(윈도우가 없는 Finder 및 닫힌 휴지통 포함)은 숨겨지고 Finder는 우측 끝에 위치), 아이콘 중앙 정렬(맞을 때; 넘치면 왼쪽에서 시작하여 스크롤), 중앙 / 최대화 버튼 표시, 로그인 시 실행. **설정...**을 클릭하면 설정 윈도우가 열리며, 세 페이지가 있습니다:

- **설정** — 아이콘 간격; 커피 잔을 탭한 후 숨김 시간(10 / 20 / 30 / 60초); 중앙 윈도우의 크기(화면 높이의 60~100%; 너비는 높이와 동일하거나 화면 너비의 50~100%); 이중 탭하여 최소화; 길게 누르여 닫기(꺼짐 / 1 / 2 / 3 / 5초) 및 스타일(봄 / 여름 / 가을 / 겨울, 터치 바에 짧은 미리보기 포함); 시스템 터치 바 제어에 양보(독립적인 스크린샷 / 녹음 및 Fn 스위치, 기본값은 켜짐); 언어(시스템 따르기 또는 12개 언어 중 하나 — 설정 페이지 상단에 표시됨; 터치 바의 길게 누르기 메시지도 번역합니다); 손쉬운 사용 권한 상태(다른 것은 필요 없음) 및 "독을 볼 수 없는 이유가 무엇인가요?" 진단.
- **사용 방법** — 제스처 및 버튼
- **정보** — 버전, 업데이트 확인, 제품 페이지 및 개발 일지 링크, 스타 버튼

앱의 독에도 아이콘이 있으므로 설치 후 거기에서 실행할 수 있습니다.

실행 중인 동안 응용 프로그램에서 앱을 다시 열면 메뉴가 나타납니다.

## 요구사항 및 테스트 환경

| | |
|---|---|
| 하드웨어 | Touch Bar가 있는 Mac(MacBook Pro 2016~2022) |
| **테스트 대상** | **MacBook Pro 13"(M1, `MacBookPro17,1`), macOS 27.0, 단일 디스플레이, 3개의 공간, "확장된 제어 스트립"으로 설정된 Touch Bar, Stage Manager 켜짐** |
| Apple silicon(M1) | ✅ 이것이 개발 및 사용되는 컴퓨터입니다 |
| Intel | ⚠️ **알 수 없음.** 다운로드는 범용 바이너리이고 Intel 슬라이스는 M1 Mac에서 Rosetta로 시작되지만, 실제 Intel Touch Bar Mac에서는 실행된 적이 없습니다. 보고 환영합니다 |
| macOS 버전 | macOS 13 최소값으로 빌드되었지만 macOS 27.0에서만 테스트되었습니다. 이전 버전은 테스트되지 않았습니다 |

알아둘 사항:

- **개인 Apple API**를 사용하여 백그라운드 앱에서 터치 바를 화면에 유지합니다. 또한 Mac App Store에 있을 수 없는 이유이기도 하며, 향후 macOS 업데이트가 중단될 수 있습니다. 개인 인터페이스는 런타임에 확인되므로, 하나가 사라지면 충돌하는 대신 해당 기능이 꺼집니다; `swift tools/probe-private-api.swift`는 macOS에 아직 있는 것을 표시합니다.
- 독은 **전체** 터치 바를 차지하므로, 시스템 제어 스트립(밝기, 볼륨)은 켜져 있는 동안 숨겨집니다. 막대의 우측에 있는 작은 커피 잔을 탭하여 독을 잠시 숨기고 터치 바를 시스템에 반환합니다(기본값 20초 후에 10~60초 후 자동으로 반환되거나, 화면이 완전히 꺼진 경우 밝기가 올라가는 즉시). 또는 메뉴에서 "터치 바에 독 표시"의 선택을 해제할 수 있습니다.
- 좌에서 우로 순서: 고정되지 않은 실행 중인 앱(최신 먼저) → 구분자 → Finder → 독 순서의 고정된 앱 → 구분자 → 휴지통. 새로 시작된 고정되지 않은 앱은 왼쪽에 보기에 들어옵니다; 열린 앱 간 전환은 순서를 변경하지 않습니다. 휴지통을 탭하여 Finder에서 엽니다.
- Stage Manager가 켜져 있으면 macOS가 윈도우 변경을 애니메이션화하므로 윈도우가 화면에 나타나는 데 약 0.5초가 걸릴 수 있습니다. 탭된 앱은 약 40ms 내에 최전면 앱이 되며; 나머지는 시스템의 애니메이션입니다.

## 설치

1. [릴리스](https://github.com/hooosberg/DockTouchBar/releases/latest)에서 `DockTouchBar-<version>.dmg`를 다운로드합니다.
2. 이를 열고 **DockTouchBar**를 **응용 프로그램**에 드래그한 다음 실행합니다. 독 아이콘이 메뉴 바 및 터치 바에 나타납니다.

> DMG는 개발자 ID 인증서로 서명되고 **Apple에 의해 공증**되었으므로, 다른 앱처럼 열립니다. macOS는 첫 실행만 확인하도록 요청합니다. 직접 컴파일하고 싶으신가요? [소스에서 빌드](#소스에서-빌드)를 참고하세요.

### 손쉬운 사용 권한(선택사항)

손쉬운 사용은 크로스 데스크톱 윈도우 전환, 이중 탭 최소화, 중앙 / 최대화, Finder의 윈도우 닫기, 확인 대화상자 감지 및 Fn 양보를 활성화합니다. 이것이 없으면 기본 시작 및 활성화만 사용할 수 있습니다; 이러한 기능은 제한됩니다.

1. 메뉴 바 아이콘 → **설정...** → **권한** → **켜기...** (한 번 부여되면 **손쉬운 사용: 켜짐**으로 읽음)
2. 시스템 설정 → 개인 정보 보호 및 보안 → 손쉬운 사용에서 DockTouchBar을 켭니다.

켜진 후에도 계속 요청하면 이전 항목이 낡았습니다(앱의 서명이 변경되었을 때 발생함): 목록에서 DockTouchBar을 선택하고 **−**를 클릭한 다음 다시 추가합니다. 또는 `tccutil reset Accessibility com.maohuhu.docktouchbar`를 실행하고 1단계를 반복합니다.

### 탭이 데스크톱을 전환하지 않으면

발생 직후에 저장소 클론에서 이를 실행합니다. 읽기 전용이며 앱이 앱의 윈도우를 판단한 방법을 출력합니다(어떤 윈도우가 있는지, 각 윈도우가 어느 데스크톱에 있는지, 어느 것이 실제 윈도우인지, 어느 것이 발생시킬지):

```bash
tools/diagnose-switch.sh com.google.Chrome
```

## 독을 볼 수 없나요?

가장 흔한 원인: 시스템 설정 → 키보드 → "Touch Bar 표시"가 "F1, F2 등. 키"로 설정되어 있으면, 전체 터치 바가 기능 키로 채워집니다. 버전 1.16 이후로 앱은 이를 감지하고 첫 시작 시 "확장된 제어 스트립"으로 전환하도록 제안합니다. 또한 메뉴 바 메뉴에서 "진단: 독을 볼 수 없는 이유가 무엇인가요?"를 클릭하여 각 가능한 원인을 확인하고 피드백을 위한 보고서를 복사할 수 있습니다. 그 후에도 Fn을 누르면 F1~F12가 계속 표시됩니다.

## 소스에서 빌드

Xcode 명령줄 도구가 필요합니다.

```bash
git clone https://github.com/hooosberg/DockTouchBar.git
cd DockTouchBar
scripts/install.sh      # 빌드 → /응용 프로그램에 복사 → 실행
scripts/make-dmg.sh     # 빌드/DockTouchBar-<version>.dmg
```

서명 인증서가 없으면 빌드는 애드 혹 서명으로 폴백됩니다. 이는 작동하지만, macOS는 모든 애드 혹 재빌드를 새 앱으로 취급하므로 매번 손쉬운 사용을 다시 부여해야 합니다. `SIGN_IDENTITY="Apple Development: …"`(또는 개발자 ID 인증서)를 설정하여 안정적인 ID를 유지합니다.

## 프로젝트 레이아웃

```
Sources/DockTouchBar/   앱 소스
Resources/              Info.plist, 앱 아이콘
scripts/                build.sh, install.sh, make-dmg.sh, make-icon.sh
tools/                  진단: 개인 API 확인, 공간/윈도우 검사기, 전환 진단, 빠른 클릭 스트레스 테스트, 오프스크린 미리보기 및 render-seasons.sh(README 스크린샷)
assets/                 README 이미지
```

큰 macOS 업데이트 후에 `swift tools/probe-private-api.swift`를 실행하여 어떤 개인 API가 여전히 사용 가능한지 확인합니다.
