### ⚡ 能耗與原生效能（早期版本實測測量）

設計用於 24/7 背景執行，使用事件驅動的應用程式和視窗更新。下表是早期版本的測量數據；螢幕截圖活動會暫時使用短時間的程序檢查：

| 指標 | 測量值 | 說明 |
|---|---|---|
| **CPU 使用率** | **0.0% ~ 0.8%** | 待機 0.0%；僅在應用程式/視窗切換事件時有短暫微小尖峰 |
| **實體佔用空間** | **29 MB** | 使用 macOS `footprint` 工具測量，遠低於 Electron 替代品 |
| **能耗影響** | **0.0** | macOS 活動監視器最低等級的能耗評分，對電池零影響 |
| **常駐執行緒** | **4 個執行緒（全部在事件上休眠）** | 零忙等待，無高頻計時器輪詢 |
| **網路存取** | **GitHub 更新檢查和下載** | 程式塢互動在本機執行；無分析或帳戶 |
| **渲染延遲** | **~2.3 ms / 影格** | 原生 CoreAnimation / AppKit 渲染管線，觸控回應瞬間 |

## 為什麼開發它

Pock、PockV2 等應用程式可以將程式塢放在觸控列上，但它們做的事更多，日常使用中觸控列容易消失或無反應。DockTouchBar 專注於做好一件事。

**簡潔**

- 專注一件事：觸控列上的程式塢。沒有小工具，沒有外掛。
- 選單列只有幾個開關，沒有其他要設定的地方。
- 原生 Swift 和 AppKit，沒有第三方相依性。像素風格場景包含在原始碼中。

**優雅**

- 使用 macOS 圖示和系統觸控列滾軸。未釘選的執行中應用程式顯示在左側，最新啟動的在最前面；釘選應用程式保持程式塢順序。關閉應用程式時保留目前可見區域。
- 不打擾的手勢：輕點立即執行（它不會等待看是否要連點），長按在圖示下方顯示安靜的進度列，加上觸控列右邊緣的「正在關閉…」倒數計時（這樣你的手指不會遮住它），以小型像素風格場景呈現，你可以在四季之間切換。提早放開可取消。
- 快速連點感覺很好：最後一次點擊總是有效的，不會與你衝突。如果系統掉落桌面切換或有東西搶走焦點，它會安靜地復原，而且一旦你觸碰鍵盤、滑鼠或觸控板，它就會停止。
- 支援你的語言（12 種語言，從英文到簡體中文和日本語），且只需一個可選權限。

**高效**

- 事件驅動的應用程式和視窗更新。M1 MacBook Pro 上的早期測量，程式塢顯示且待機時：**0.0% CPU**、**0 個閒置喚醒**、約 **32 MB** 記憶體。\*
- 適應你的 Mac 而不是使用固定延遲：桌面切換等待系統自己的「完成」訊號並檢查結果，所以無論動畫快或慢、是否關閉，或機器是否繁忙都能保持正確。
- 當應用程式啟動或關閉時，只有變化的部分會更新，滾動位置保持不變。圖示只點陣化一次並快取。
- 自我修復：在睡眠、螢幕解鎖和控制條重啟後自動重新連接，所以你永遠不需要重新啟動它。
- 安全失敗：私有 API 在執行時解析。如果 macOS 移除某個，該功能會自動關閉而不是當機。
- 隱私：無分析或帳戶。程式塢互動在本機執行；自動更新檢查和要求的下載連接到 GitHub。偏好設定保留在你的 Mac 上。

<sub>\* 發行版本。CPU 來自五個 `top` 樣本，間隔 2 秒（全部 0.0%）；喚醒來自核心的各程序計數器，間隔 20 秒讀取，在 1.10 上測試三次（閒置喚醒和中斷喚醒每次都是 0；在 1.8 的較早執行中看到 0–7 個中斷喚醒，來自系統事件）；記憶體是來自 `footprint` 的實體佔用空間（32 MB）。咖啡杯上方的蒸汽由系統渲染程序繪製，不是由應用程式繪製。</sub>

## 功能

| 手勢 | 發生的情況 |
|---|---|
| **輕點**圖示 | 切換到該應用程式，或啟動它。如果應用程式的視窗在另一個桌面（空間），跳到該桌面 |
| **連點** | 最小化目前視窗，如同按其黃色按鈕。需要輔助使用權限。再點一次可還原 |
| **長按** | 關閉應用程式，並始終告訴你發生了什麼。按住時圖示下方會填滿進度列，右邊緣出現「正在關閉…」倒數計時，顯示像素風格季節場景（你可在選單中選擇）；提早放開算作一次輕點。應用程式總是完全關閉（與 ⌘Q 相同），無論有多少視窗或是否最小化或隱藏。尋找工具無法關閉，所以它的所有視窗都會關閉（包括最小化的；如果視窗在另一個桌面，先跳到該桌面）。如果應用程式因為在等待你（「未保存變更」提示）或無法關閉，觸控列會切換到它，跨越桌面，並告訴你這一點 |
| **廢紙簍** | 輕點以在尋找工具中打開廢紙簍視窗；連點最小化它；長按關閉它。視窗關閉時變暗（在「只顯示執行中應用程式」模式下消失） |
| **滑動** | 圖示放不下時滾動；關閉應用程式時保留目前區域在檢視中 |
| **咖啡杯**（右端，有動畫蒸汽） | 休息一下：暫時隱藏程式塢並將觸控列還給系統（亮度、音量）。它在 10–60 秒後自動返回 |
| **居中 / 最大化按鈕**（最右端） | 居中最前面應用程式的視窗；再點一次最大化它（填滿可用區域，不是原生全螢幕），再點一次回到居中。如果你自己移動視窗或切換應用程式，它先居中，圖示跟隨視窗目前狀態。需要輔助使用權限 |

選單列選單保留日常開關：在觸控列上顯示程式塢、只顯示執行中的應用程式（預設關閉：也顯示釘選應用程式；會變灰的應用程式（包括沒有視窗的尋找工具和已關閉的廢紙簍）隱藏，尋找工具在最左邊）、圖示居中（當圖示放得下時；溢出時從左邊開始滾動）、顯示居中 / 最大化按鈕、登入時啟動。**設定…**打開設定視窗，有三頁：

- **設定** — 圖示間距；點咖啡杯後隱藏的時間（10 / 20 / 30 / 60 秒）；居中視窗的大小（螢幕高度的 60–100%；寬度與高度相同，或螢幕寬度的 50–100%）；連點最小化；長按關閉（關閉 / 1 / 2 / 3 / 5 秒）及其風格（春季 / 夏季 / 秋季 / 冬季，觸控列上有短預覽）；讓步給系統觸控列控制項（獨立截圖 / 錄製和 Fn 開關，預設開啟）；語言（跟隨系統，或 12 種語言之一 — 顯示在設定頁最上方；它還翻譯觸控列的長按訊息）；輔助使用權限狀態以及系統設定的捷徑（沒有其他需要權限）；以及「為什麼看不到程式塢？」診斷
- **使用方法** — 手勢和按鈕
- **關於** — 版本、檢查更新、產品頁面和開發日誌連結、Star 按鈕

應用程式在程式塢中也有圖示，所以安裝後可以從那裡啟動它。

從應用程式資料夾再次打開應用程式（當它執行時）會彈出選單。

## 需求和已測試環境

| | |
|---|---|
| 硬體 | 配有觸控列的 Mac（MacBook Pro 2016–2022） |
| **測試於** | **MacBook Pro 13 吋（M1，`MacBookPro17,1`），macOS 27.0，單一顯示器，3 個空間，觸控列設為「展開的控制條」，Stage Manager 開啟** |
| Apple 晶片（M1） | ✅ 這是開發和使用的機器 |
| Intel | ⚠️ **未知。** 下載是通用二進制，Intel 部分在 M1 Mac 上以 Rosetta 啟動，但從未在真實 Intel 觸控列 Mac 上執行過。歡迎回報 |
| macOS 版本 | 使用 macOS 13 最低值編譯，但僅在 macOS 27.0 上測試。較舊版本未測試 |

需要知道的事項：

- 它使用 **私有 Apple API** 以從背景應用程式保持觸控列在螢幕上。這也是為什麼它無法在 Mac App Store 上線，為什麼未來 macOS 更新可能會破壞它。私有介面在執行時解析，所以如果其中一個消失，該功能會自動關閉而不是當機；`swift tools/probe-private-api.swift` 顯示你的 macOS 仍有哪些。
- 程式塢佔據**整個**觸控列，所以系統控制條（亮度、音量）在它開啟時被隱藏。輕點列右側的小咖啡杯以隱藏程式塢一會兒，並將觸控列還給系統（它在 10–60 秒後自動返回，預設 20 秒 — 或者，如果螢幕被完全調暗，一旦亮度提高就立即返回）。你也可以在選單中取消勾選「在觸控列上顯示程式塢」。
- 由左到右順序：未釘選的執行中應用程式（最新啟動的優先） → 分隔線 → 尋找工具 → 釘選的應用程式（程式塢順序） → 分隔線 → 廢紙簍。新啟動的未釘選應用程式進入左側檢視；在開啟應用程式之間切換不會重新排序它們。輕點廢紙簍以在尋找工具中打開它。
- 啟用 Stage Manager 時，macOS 會為視窗變更製作動畫，所以視窗可能需要大約半秒才能出現在螢幕上。輕點的應用程式約在 40 毫秒內成為最前面的應用程式；其餘是系統的動畫。

## 安裝

1. 從 [Releases](https://github.com/hooosberg/DockTouchBar/releases/latest) 下載 `DockTouchBar-<版本>.dmg`。
2. 打開它，將 **DockTouchBar** 拖到 **Applications**，然後啟動它。程式塢中和觸控列上會出現圖示。

> DMG 使用 Developer ID 憑證簽署並**由 Apple 公證**，所以它開啟方式與任何其他應用程式一樣。macOS 只會在首次啟動時要求確認。想要自己編譯？見[從原始碼編譯](#從原始碼編譯)。

### 輔助使用權限（可選）

輔助使用可啟用跨桌面視窗切換、連點最小化、居中 / 最大化、關閉尋找工具視窗、偵測確認對話方塊，以及 Fn 讓步。沒有它，基本啟動和啟用仍然可用；這些功能會受限。

1. 選單列圖示 → **設定…** → **權限** → **開啟…**（授予後顯示為**輔助使用：開啟**）
2. 在系統設定 → 隱私與安全 → 輔助使用中，開啟 DockTouchBar。

如果開啟後仍然詢問，舊條目已過時（應用程式簽署變更時會發生）：在清單中選擇 DockTouchBar，按 **−**，然後重新新增。或執行 `tccutil reset Accessibility com.maohuhu.docktouchbar` 並重複步驟 1。

### 如果輕點無法切換桌面

出現問題後立即從回購複製執行此。它是唯讀的，並列印應用程式如何判斷該應用程式視窗（存在哪些視窗、各自在哪個桌面、哪些是真實視窗、會提高哪一個）：

```bash
tools/diagnose-switch.sh com.google.Chrome
```

## 看不到程式塢？

最常見的原因：系統設定 → 鍵盤 → 「觸控列顯示」設為「F1、F2 等鍵」，這會用功能鍵填滿整個觸控列。自 1.16 起，應用程式會偵測這個並在首次啟動時提議改為「展開的控制條」。你也可以點選選單列選單中的「診斷：為什麼看不到程式塢？」來檢查每個可能的原因並複製回報用的報告。之後按住 Fn 仍會顯示 F1–F12。

## 從原始碼編譯

需要 Xcode 命令列工具。

```bash
git clone https://github.com/hooosberg/DockTouchBar.git
cd DockTouchBar
scripts/install.sh      # 編譯 → 複製到 /Applications → 啟動
scripts/make-dmg.sh     # build/DockTouchBar-<版本>.dmg
```

沒有簽署憑證時，編譯回退到臨時簽署。這有用，但 macOS 將每個臨時簽署重建視為新應用程式，所以你每次都要重新授予輔助使用權限。設定 `SIGN_IDENTITY="Apple Development: …"`（或 Developer ID 憑證）以保持一個穩定身份。
